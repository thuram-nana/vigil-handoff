**The hole (confirmed in code):** `verify/oracles.py::predicate_oracle` PD2 fires `eq[acao, evil_origin]` where `acao` is the CAPTURED server ACAO header and `evil_origin` is the injected canary (scanner/checks.py ~859-868; host ~880, redirect ~936). A fully-untrusted in-process OFFENSE-plane producer (TM-B) authors `observed` (web_redrive.py ~1435 captures in-process), the cert is signed by OFFENSE-GOVERNANCE m-of-n keys (oracle_adapter.py ~113 — keys the producer is in-process with), and offline `framework.v2 verify` re-runs the PURE oracle over the SAME retained `observed` → a FALSE signed FACT that re-verifies CLEAN. predicate_oracle's own docstring admits it "cannot prove observed is a GENUINE capture" and defers genuineness to "the certificate signature" — but that signature is offense-held, so it does NOT defend against an offense-plane adversary.

**The theater trap (why the obvious fix fails):** a SIGIL-signed per-injection attestation binding {engagement, probe, key, VALUE} (sovereign signs, offense verifies keyless — a clean, FATAL-2-safe, byte-identical, no-false-refusal design) **does NOT close TM-B**. It is a TRUST-MOVE: it makes the INJECTED value (`observed[evil_origin]`) unforgeable-as-a-value, but PD2's claim is "the target REFLECTED our canary", and that lie lives in the CAPTURED operand (`observed[acao]`), which the attestation never touches. The producer obtains `V` = the real attested canary value (the design even derived it deterministically from `digest_payload`, so offense KNOWS it), sets `observed={acao:V, evil_origin:V}`, attaches the REAL attestation → PD2 fires, signature verifies, false FACT re-verifies clean. No forgery, no replay. PD2 never needed the canary to be a SIGNED value; it needed it SECRET from the reflection-forger — and the offense plane must know the canary to inject it, so it can never be secret from itself. Relocating trust from one producer-settable slot (`provenance_refs` key-membership, oracles.py ~1348) to another (a signed value the producer also holds) is the Slice-1 theater the [[achieved-state-sampling-unsound]] / [[fake-fixture-pattern]] discipline warns about.

**The ONLY sound close:** attest the CAPTURE, not the injection. Bind the CV (captured-var) operand to a NON-OFFENSE RESPONSE-collector receipt — the VF-2b OOB pattern (`verify/oob.py:94-111` `sign_oob_receipt`/`verify_oob_receipt`, whose core signs "only TARGET-observed facts", pinned on the verifier out-of-band like `oob_collector_pubkey` at verifier.py ~1229) applied to the in-band HTTP RESPONSE — minted by a collector/signing-proxy whose key the in-process offense producer cannot hold. Then PD2 admits only when the CAPTURED operand's value is covered by a receipt verifying against the pinned root. **That collector does not exist today**, and routing the live reflection capture through a non-offense signing proxy is an architectural change with an operator-infra/deployment dimension (collector independence) — so it is a FRONTIER piece, NOT a bounded buildable-now slice. PD4 (idor/exposure present-absent differential) and PD3-reduction are ALSO not closed (same root: the discriminator is a producer-authored CAPTURE).

**The general invariant this exposes (load-bearing for the gold-standard claim):** the "re-verify without trusting us" promise is sound ONLY for facts backed by a signature from a key the OFFENSE plane does not hold — i.e. a SIGIL/owner signature or an OOB-collector signature. The **in-process-capture classes** (reflection PD2, most ACHIEVED_STATE) are sound against the NORMAL gated pipeline (trusted runner + governance signature) but carry a NAMED TM-B residual that a fully-compromised offense plane could forge; closing it needs a non-offense capture-attestation channel. VF-2b OOB classes are the exception already sound against TM-B (the collector is non-offense). Do NOT claim TM-B "closed" for the in-process-capture classes; keep the oracle-docstring boundary honest. [[vigil-gold-standard-program]] [[weaponized-arm-corpus-provenance-triplelock]]

**Process win:** a design→adversary PRE-TEST (read-only, before any build) caught this; the design's engineering properties (byte-identity, FATAL-2-keyless, no-false-refusal) all HELD but were MOOT because the central security goal was unmet. Run the adversary pre-test before building the hardest/most-novel soundness slices — it is cheaper than a red-penned build of theater.
