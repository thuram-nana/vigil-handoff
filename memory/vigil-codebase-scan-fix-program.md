**The gap it closed:** the codebase scan produced findings that never reached the UI, and the fix could NEVER run — `vigil patch --from-spine` needs a signed `<slug>.spine`, but no codebase scan wrote one (only the URL engine does, and `vigil engage` is URL-only). So `fix_precondition` always refused.

**Design (operator chose the deterministic DAA static-oracle):** a codebase has no live HTTP oracle, so a finding is grounded in a DAA (Deep Analysis Arsenal, `framework.v2.analysis`) static rule that MATCHED real source bytes — a re-runnable STATIC fact (re-run the rule → fires or not), NOT a live-exploit claim.
- NEW **`vigil codescan`** verb + `integration/vigil_integration/codescan.py`: runs DAA, writes each finding into the signed `<base>/<slug>.spine` as `Finding(status="fact", evidence_ref="sha256:"+digest_payload(daa_match), source="daa:<rule_id>", target="path:line")`, emits CWE-tagged findings JSON. `--verify --ref <ref>` = the fix oracle (re-run DAA; exit 0 iff rule fires NOWHERE).
- Console `mode=sast` spawns `vigil codescan` (capture_report → report.json → Findings screen); `fix_precondition` accepts `mode in (codebase,sast)` + reads base_dir from meta; the existing tested gated ladder (`vigil patch --from-spine … --apply-edits --approve`) then proposes+applies a diff to a DISPOSABLE clone (never the operator tree, never a PR). NEW `verify_fix` + `/api/remediate/<run>/<ref>/verify`.
- Added optional `Finding.target` (agent/state.py) + `TriageFinding.source` so the fix proposer can locate the file and the daa: qualifier survives. New Assessment "Scan a codebase" defaults to DAA (Strix toggle); Fixes screen gains a "Verify (re-scan)" button.

**Verified live** vs a planted vuln app: 7 CWE-tagged facts → signed spine round-trips through `finding_from_spine` (crypto `confirmed=True`) → `vigil patch` proposes+applies (`applied_paths=['app.py']`) → verify flips cleared False→True.

**Adversarial review (dual) caught REAL defects — all fixed:**
- **HIGH (verify false-fixed):** the verify oracle used an EXACT-PATH filter, so a MOVED/renamed vulnerable file reported `cleared=True` while still present. Fix: `cleared` = rule fires NOWHERE (rule-anywhere) + a `moved` flag. Lesson: a fix-verify oracle must be conservative — rule-anywhere, never per-path.
- **make_ref/parse_ref not inverses/argv-safe** for external rule ids (semgrep/gitleaks) with `~`/space/leading-dash → false-clear + un-actionable. Fix: rpartition parse + fully-b64 `Z~…` fallback for dirty ids; clean DAA-* stay readable.
- **Overclaim:** a DAA regex hit rendered identically to a live-exploit "FACT (oracle-confirmed)". Fix: label it a **STATIC** fact (distinct verdict/chip); softened verify copy to "the rule no longer fires" (proves pattern gone, not runtime reachability).
- **Spine shadowing:** codescan wrote `seq=1` into a fixed slug/base → a re-scan or 2nd repo shadowed findings by hash order. Fix: MONOTONIC seq (head_seq+1) + UNIQUE per-run slug.
- **LOW:** report.json (may carry a matched secret line) → 0600.

**Gotchas:** the fix ladder's verify runs ONLY post-PR (remediated is type-locked to require an opened PR), so the console (never --open-pr) proposes+applies+sandbox-builds but never mints "remediated" — the deterministic DAA re-scan is the console's verify instead. `make deploy-console`'s restart does NOT reload the long-lived `crucible api` — always `systemctl --user restart vigil-command.service` and check the real `:8799` listener's start time. codescan.py keeps framework/vigil_core imports FUNCTION-LOCAL (only reached via the `vigil` CLI subprocess) to respect the two-env boundary; its test importorskips framework + is on the offense-leg run-list.
