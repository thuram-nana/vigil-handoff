**PROBLEM 1 — whole-app suite under-promotes in-band injection FACTs (SQLi/XSS/SSTI/path-traversal/cmdi stay LEADs; only cheap CWE-200 `exposure` mints).** Root cause (grounded): the console suite forces `--request-budget` from `_ENGAGE_DEPTH={quick:60,standard:200,deep:500}` (console/actions.py:349,3047) but the engine's OWN default is **1000**, raised from 200 precisely because the boolean_sqli SPRT "can consume 200 on the audit ALONE" (engage.py:1046-1055). `run_engagement` never sets `targeted`, so `selector=None` → ALL ~160 checks (DEFAULT_CHECKS + 172-entry library incl. the multi-round BOOLEAN_SQLI_SPRT ~64 req/boolean-point) run at EVERY insertion point (campaign.py:390,1447; engine.py:595). The single shared budget (sticky BudgetExceeded — the terminal-stop fix from [[vigil-vps-deployment]]) is spent by the crawl of ~29 endpoints (= the ~300 passive-hygiene LEADs) + the first endpoints' point-sweeps BEFORE the serial sweep reaches the injection sinks → those classes never conclusively probed → inconclusive → "adjudicated 0/22 point-check classes / VERDICT BOUNDED" (campaign.py:243-347). `exposure` is a REQUEST-level signature check, run once per host, cheap, and OUTSIDE the point-check denominator → that is why 2-4 exposure FACTs coexist with 0/22. `--autonomous` is a SEPARATE tiny pass (budget 8, 1 cycle) wrapping only a single REFLECTED_XSS → it fires "xss @ /documents/download" (wrong check for a traversal sink) and can't mint sqli/ssti/etc. Blind OOB classes (ssrf/blind_xxe/cmdi) additionally can't VF-2b confirm without a pinned collector; a greenfield loopback engage pins none (engage.py:435-449) → inconclusive BY DESIGN ([[vigil-oob-subsystem-and-authority-gate]]). FIXES: operator-now = run the engage CLI directly with `--request-budget 1000 --library` (engine default) or UI "deep"; code = raise/scale `_ENGAGE_DEPTH` by endpoint count; enable `targeted=True` for the suite ONLY WITH the selector-pairing fix (targeting.py:27-34,46,67,71-77 + engine.py:595 — currently called without `reflected=True` so SSTI is dropped, and `host` maps to ssrf/open_redirect but NOT command_injection, and by_class.setdefault collapses variants); pin a loopback OOB collector for the owned range.

**PROBLEM 2 — UI freezes/slows/lags once a run starts (VPS is idle/healthy → CLIENT-side, not server).** Root cause (grounded): (A) the **Live screen `#/live`** re-renders synchronously on EVERY SSE event — `L.events.push(ev); onEvents()` (app.js:3073,3085) → `updateHeader`(O(n) counts() rescan) + `drawTimeline` which rebuilds a DOM row for the WHOLE uncapped buffer via full `V.mount` teardown+rebuild (app.js:3019 no cap; 3352-3362; ui.js:47-48), no throttle/debounce/rAF (0 requestAnimationFrame in app.js) → **O(n^2)** over the run; plus a `.new` 0.4s fadein re-runs on every row each rebuild (components.css:277). (B) engine floods: each of 60 OOB library checks BLOCKS up to `poll_deadline=2.0s` (checks.py:733,755-759) even when no collector is pinned (only skip is `self.oob is None`, engine.py:413-416) → long "nothing happening" stalls; and every LEAD is posted as kind="finding" so MultiCriticAgent writes 3 synchronous `critic_verdict` spine commits PER LEAD (critics.py:220-249; engage_autonomous.py:108-123; blackboard.py:527-537). FIXES: operator-now = watch heavy runs from Findings/Runs not `#/live` (teardownLive stops the O(n^2) path, app.js:2847); enable OS "Reduce motion" (components.css:783 already honors it). code = rAF/debounce-batch Live `onEvents` (model on PBOX's pboxScheduleRender app.js:10955); cap+incrementally-append the timeline (app.js:3352); gate critics to oracle-carrying findings (kills the per-lead flood — helps BOTH problems); batch the OOB drain into ONE deadline window per endpoint keeping per-token adjudication SERIAL (checks.py:740-767; engine.py:594-632 — do NOT re-add concurrent timing, phase-lock per [[timing-concurrency-phase-lock]]).

**RESOLUTION (2026-10-19, same session, verified vs a LOCAL vuln MERIDIAN on :19020).** The "only 2-4 facts" cmdi case was MULTI-FACTOR and is now closed:
- **cmdi = the ONE true in-band oracle gap** (every existing cmdi check was OOB/timing; nothing keyed on the reflected `id` output). Closed by **`CmdiReflectedCheck`** (scanner/checks.py, commit **c4f4def1**): confirms via the EXISTING `side_effect_oracle` on the execution-only anchored signature `(?<![0-9A-Za-z_])uid=\d+\(` (a property of `id` RUNNING, not of input echo — the payload carries no `uid=`), attributed by a benign `127.0.0.1` control. Payloads `;id`/`|id`/`$(id)` (read-only). Red-penned (claims 1-6 held). In DEFAULT_CHECKS at a <=3-req tier.
- **Targeting shadow (red-pen caught a REAL bug I introduced):** `select_checks` deduped per `bug_class` (`by_class.setdefault`), silently shadowing the in-band cmdi check behind the OOB `rce-oob` (`;curl {callback}`) one on the targeted/autonomous path (orchestrator hard-codes targeted=True) → an in-band-only cmdi sink confirmed by NOTHING. **Fixed to dedup per `(bug_class, channel)` keyed on `wants_oob`** (OOBCheck/DNSOOBCheck set it True; response checks don't), keeping BOTH channels. LESSON: an OOB (callback-confirmed) and an in-band (response-confirmed) check for the same class are NOT interchangeable — never collapse them.
- **CORRECTION to PROBLEM 1's OOB claim:** the ENGINE engage (`framework.v2 engage` / `run_engagement`, what the console suite + `vigil onboard` launch as a subprocess) admits FACTs via the **veracity firewall**, NOT `runtime_redrive`, AND it DOES set up a LOCAL loopback OOB receiver for the audit phase — so `rce-oob` (`;curl {callback}`) CAN fire against a genuinely-calling-back target. MERIDIAN's `/diagnostics/ping` runs `ping -c1 -w2 host;curl <cb>` for real, so at adequate budget cmdi confirms via **OOB_CALLBACK** (0.95). So cmdi has TWO channels on engage now: OOB (needs a reachable callback) + in-band reflected `uid=` (Slice A, needs no collector — the egress-blocked-target path). `runtime_redrive`'s OOB-only cmdi arm (needs a PINNED collector) is a SEPARATE governed/Strix seam; an in-band arm there = "Slice B" (NOT done — mints new signed FACTs, carries a named residual, needs its own red-pen; cmdi already mints on the primary routes without it).
